### 1. フォロー解除・申請の取り消しで、元の Follow の id を参照する (#18163)

- upstream: `59352ed4f4`。本家は、送った Follow の id (`/follows/<申請の行の id>`) と、Undo / Reject の中の Follow の id (`/follows/<follower>/<followee>`) が食い違っていた。直し方は次の 3 つ

  - リモート → ローカルのフォローでは、受けた Follow の id を `following.requestId` に残す (フォロー済みのところへ再び Follow が来たら上書きする)。申請を承認したときも引き継ぐ。ローカルの人がリモートのフォロワーを外す・ブロックするときの Reject は、その id の Follow を包む

**残る差は 2 つ。**

- **migration が無い。** `internal/model/following.go` に `requestId` は無く、`migration/` にも無い。TS から移した DB には列があり、TS 2026.11.1 の migration の記録もあるので、Elythia が作る DB にも列と TypeORM の migration の記録 (`FollowingRequestId1794917481157`) が要る。版を上げると `TestMigrationSeed_CoversUpstream` (`internal/entitycompat/migration_seed_test.go`) が名前の漏れで落とす

- 対応:
  - 新しい migration で `following."requestId"` (varchar(512)、NULL 可、本家と同じ列のコメント) を `ADD COLUMN IF NOT EXISTS` で足す (TS 2026.11.1 から移した DB には既に列がある。`migration/000134_announcement_auto_archive_at.up.sql` と同じ形)。down は `DROP COLUMN IF EXISTS` にし、Follow の id が失われることをコメントに書く。TypeORM の migration の記録 `FollowingRequestId1794917481157` は、版を上げるコミットで入れる。DDL を先に入れてから名前を書く (`migration/000135_migrations_typeorm_names_2026_10_1.up.sql` と同じ方針)

### API のルートを GET と POST だけ登録する (#18190、影響なし)

- upstream: `34cbfe36d2`。本家は endpoint を `fastify.all` で全メソッドに登録していたのを、GET / POST だけにした (Node の性能の修正)

Elythia は元から `apiRoutes` の `POST` / `GET` / `Match` でメソッドごとに登録している (`internal/server/json_binder.go:451-473`)。

**実装の後に分かったこと (#4277)。**

- 本家はこの変更で、endpoint の外で直接登録する `/clear-browser-cache` も `fastify.route({ method: ['GET', 'POST'], url, handler })` の形にした。paramDef の抜き出し (`tools/paramdefspec/extract.mjs` の `directRoutes`) と `docs/api-compat.md` を作る `tools/apicompat` は、この形を読めずにルートを黙って落としていた (api-compat.md では Elythia 独自に数えられる)。両方がこの形を読むよう直し、読めない `fastify.route` があれば落とすようにした (版を上げるコミットの前のコミット)
- GET・POST・HEAD 以外のメソッドへの応答には差が生じた。本家 2026.11.0 は `fastify.all` で受けていたが、2026.11.1 は登録の無いメソッドを fastify の既定の 404 にする。HEAD は fastify の `exposeHeadRoutes` (既定で有効。本家は指定していない) が GET のルートと同じ handler に届けるので、`/clear-browser-cache` では本家も Elythia も 405 になる。Elythia は `/clear-browser-cache` に 405、endpoint には `/api/*` の catch-all の 200 (`{}`) を返す。実際のクライアントは使わないので、diff-e2e などでは比べない。`/clear-browser-cache` の差は `docs/divergence/api.md` に記録した

### IPv6 の HTTP プロキシ (#18155、既対応)
