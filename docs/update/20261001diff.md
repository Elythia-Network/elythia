minor release だが、**中身の大半はセキュリティ修正とその review fix** (`Merge commit from fork` 5 件と、#17987 / #17991 の review fixes)。それ以外は backend の不具合修正 4 件 (署名の `(request-target)`、クリップ、ファイル配信 2 件)、frontend の修正 3 件、依存 / 翻訳の更新。

## 移植優先度: 高 (セキュリティ)

### 1. ログインしていない閲覧者に見せる範囲 (`ugcVisibilityForVisitor`) を広げる (SEC, #17987)

- upstream: `3bea204ac5`。`QueryService.generateUgcVisibilityQueryForVisitor` を足し、ログインしていない閲覧者の読み取りのほぼすべての経路 (グローバルタイムライン、`/api/notes`、featured、タグ検索、検索、`users/notes`、`channels/timeline`、ストリーム、Web のフィード、pack 時の非表示など) に設定を効かせた

**mk-go は部分対応だった (#3289 で対応済み)。** 効いていたのはノートと利用者の単体表示、タイムラインの `none`、SSR だけだった。判定を `core/ugcvisibility` にまとめ、本家と同じ経路に効かせた。

- **AP の outbox には効かせない。** 本家は `FanoutTimelineEndpointService` が `me == null` のとき常に絞るので outbox まで巻き込まれるが、連合の互換を優先する (`docs/divergence.md` §6)
- Meilisearch のローカル限定の条件 (`userHost IS NULL`) は、mk-go がこれまで `userHost` を省いて索引していたため一致しなかった。属性が無い文書にも一致する形に直し、これから索引する文書は本家と同じく null を持つ

### 2. フォロー・フォロワー一覧の公開範囲 (SEC, fork merge)

- upstream: `a10fdf706c`。`federation/followers` / `federation/following` に、一覧の持ち主のフォロー・フォロワーの公開範囲の条件 (`generateFollowingRelationVisibilityQuery`) を足した。あわせて #17987 でリモート利用者の公開範囲を相手の collection から決める (`isPublicCollection`)

**mk-go は未対応だった (#3287 で対応済み)。** インスタンスごとの一覧を SQL で絞り、actor の取り込みと更新で `followers` / `following` の collection を本家と同じ規則で見て保存する。別ホストの collection を取りに行かない点などは `docs/divergence.md` §3-3。

### 3. #17987 のその他の review fix (SEC)

いずれも **#3286 で対応済み**。

- **Web のフィード** (`FeedService`): 著者の `makeNotesHiddenBefore` / `makeNotesFollowersOnlyBefore` に当たる投稿を出さない
- **翻訳** (`notes/translate`): 本家の `isHidden` に当たる投稿を翻訳しない
- **`get-avatar-decorations`**: ログインしていない利用者には公開ロールの id だけを返す
- **ロールのタイムラインのストリーム**: 公開かつ探索可能なロールに限る (mk-go は探索可能だけを見ていた)
- **チャットのリアクション**: 本家と同じアクセス検査をし、エラーを `NO_SUCH_MESSAGE` にそろえる

### 4. Meilisearch の検索条件のエスケープ (SEC, #17991)

- upstream: `03bc96654c`。検索条件の値をバックスラッシュでエスケープするようにした (それまでは `// TODO: escape`)

**mk-go は部分対応だった (#3286 で対応済み)。** エスケープはしていたが形が違ったので、本家と同じ形にそろえた。

### 5. Web Push の購読先の検証 (SEC, fork merge)

- upstream: `4ef6cbe2af`。`sw/register` で購読先を検証し、`INVALID_ENDPOINT` で断る。配送でも検証する

**mk-go は部分対応だった (#3286 で対応済み)。** 配送側の SSRF 対策は `safehttp` で入っていたが、登録時の検証と API のエラーが無かった。`golden_error_ids.json` に `sw/register` の `INVALID_ENDPOINT` が加わる。

### 6. `sw/unregister` のパラメータ (SEC, fork merge)

- upstream: `367daf868a`。`sw/unregister` が `endpoint` に加えて `auth` / `publickey` を必須で受け取り、レート制限 (1 時間 30 回) が付いた。frontend もこれらを送るようになる

**mk-go は未対応。追従 PR (#3285) で対応する。** frontend が新しいパラメータを送るのは submodule を上げてからなので、bump のコミットの後に置く。購読キャッシュの無効化 (本家の `register` / `unregister` が `refreshCache` を呼ぶ) もあわせて入れる。

## 移植優先度: 中

### 7. 非同期で処理する inbox の `(request-target)` に query を含める

- upstream: `7c9c38c04a` (#17941)。送信側の署名で `(request-target)` を `pathname` だけで作っていたのを、query 込みにした (空の `?` も残し、fragment は落とす)

**mk-go は送信側と同期の受信検証は既対応** (`req.URL.RequestURI()` を使う)。**非同期の受信検証だけが query を落とす** — inbox の handler が path だけを queue に積むので、worker 側で組み直した `(request-target)` が合わない。

- 対応: queue に `URL.RequestURI()` を積む。既存の payload は path だけなので後方互換。難易度 S

### 8. クリップから入っていないノートを外す

- upstream: `4682d44cae` (#17974)。削除件数が 0 なら 400 `NO_SUCH_NOTE` (`aff017de-190e-434b-893e-33a9ff5049d8`) を返し、削除できたときだけ `clippedCount` を減らす

**mk-go は部分対応。** 逐次の繰り返しでは負にならないが、並行した削除では両方が減らしうる。クリップに入っていないノートの削除は 204 を返していた (本家 2026.10.0 は 400)。

- 対応: 削除件数を返す repository メソッドで判定する。upstream-e2e の `clips.ts` に追加されたテストはこれで通る。難易度 S

### 9. リレーの Accept / Reject を申請中のときだけ受け付ける (#17987)

- upstream: `RelayService.updateRequestingRelayStatus` が送り主の inbox をリレーの inbox と突き合わせ、`status = 'requesting'` の行だけを更新する

**mk-go は部分対応。** 送り主の検査 (actor のホストとリレーの inbox のホスト) はあるが、状態の条件が無いので、承認済みのリレーが後から拒否に変わりうる。

- 対応: 条件付きの UPDATE。`docs/divergence.md` の「upstream は送信者が当の relay かを見ない」は古くなったので書き直す。難易度 S

### 10. `notes/polls/vote` の見えないノート (#17987)

- upstream: 見えないノートへの投票を 400 `NO_SUCH_NOTE` (`ecafbd2e-c283-4d6d-aecb-1a0a33b75396`) で断る

**mk-go は可視性の検査は既対応だが、エラーが `ACCESS_DENIED` だった。** 存在しないノートと同じ応答にそろえる。難易度 S

### 11. `notes/featured` を絞り込みの後で件数まで埋める (#17987)

- upstream: `slice(0, limit)` をミュート・ブロック等の絞り込みの後へ移した

**mk-go は未対応。** ranking を `limit` で切ってから絞るので、1 ページが欠ける。ranking は件数が限られるので全部を引いてから切る。難易度 S
